# Источники и границы проверки

## Использованный материал

[Предоставленная переписка «Анализ инцидента»](https://chatgpt.com/share/6aa97916-b70c-83eb-bb74-ac33651617c5) — источник контекста, пересказа событий, идентификаторов и формулировки четырёх пунктов Задачи 1. Это вторичный источник, а не замена исходным артефактам.

## Оригиналы, необходимые для сверки

| Артефакт | Название из переписки | Статус |
|---|---|---|
| A | `spec-fragment.pdf` | Не предоставлен в этом проекте |
| B | `logs-excerpt.log` | Не предоставлен в этом проекте |
| C | `app-screenshot.png` | Не предоставлен в этом проекте |
| Полное условие | `test-assignment.pdf`, README | Не предоставлено в этом проекте |

После добавления оригиналов следует проверить цитаты, время, значения ID и добавить точные ссылки на строки/страницы. В текущей версии таких ссылок нет, чтобы не создавать видимость проведённой проверки.

## Редакторские уточнения

- Успешный ответ создания счёта отделён от прямой проверки документа в 1С.
- Связь DLQ → N/A обозначена гипотезой.
- Kafka offset рассматривается вместе с topic и partition.
- Позднее `lag=0` не используется как доказательство успешного биллинга.
- Ранний UI и поздняя отчётность не представлены единым снимком состояния.
- Проверка через GET не заменяет серверную идемпотентность.
