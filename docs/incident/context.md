# Контекст и допущения

## Сценарий

Водитель завершает обмен на точке 3 маршрута M-148. Приложение показывает ошибку сохранения; водитель повторяет действие. Позже финансовый реестр показывает отсутствие счёта и необходимость ручной обработки.

По пересказу логов, первая попытка уже создала счёт в 1С. Расследование должно объяснить, почему разные компоненты показывают разные результаты одной операции.

## Допущения, влияющие на вывод

1. `exchange_id=ex-20260824-0010482` в двух запросах обозначает **одну** бизнес-операцию. Совпадения ключа недостаточно: необходимо сравнить payload, клиента, точку и дату.
2. Оба запроса имеют одинаковую значимую нагрузку. Если во втором изменилось количество ковров, это потенциальный конфликт данных.
3. Идентификаторы строк БД и сообщений в пересказе относятся к одному окружению. Kafka offset сопоставляется только вместе с topic и partition.
4. Время между компонентами сопоставимо. До проверки часовых поясов и синхронизации часов интервалы считаются ориентировочными.
5. Сообщение `Invoice created OK` свидетельствует об успешном ответе интеграции. Существование, актуальность и принадлежность документа проверяются непосредственно в 1С.
6. Финансовый реестр может быть отдельной проекцией. Его алгоритм в доступном тексте не описан.

## Что считается доказательством

| Уровень | Что означает |
|---|---|
| Наблюдение из переписки | Значение или событие приведено в предыдущем разборе; оригинал ещё не проверен |
| Вывод | Объяснение, согласующееся с наблюдениями при указанных допущениях |
| Гипотеза | Возможный механизм, для которого нужны дополнительные данные |
| Риск | Возможный сценарий отказа, не установленный как причина этого инцидента |
